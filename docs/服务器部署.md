# 服务器部署指南（Linux + Docker）

本指南用于在一台**已安装 Docker 与 Docker Compose v2** 的 Linux 服务器上，通过一键脚本 `deploy.sh` 部署闲鱼监控系统。

> 如果服务器还没装 Docker，先安装：
> ```bash
> curl -fsSL https://get.docker.com | sh
> sudo usermod -aG docker $USER   # 让当前用户免 sudo 使用 docker（重新登录后生效）
> ```

## 一、拉取代码

```bash
git clone https://github.com/samuelycx/ai-goofish-monitor.git
cd ai-goofish-monitor
```

## 二、一键部署

```bash
bash deploy.sh
```

**国内服务器**拉取 `ghcr.io` 通常很慢，建议直接优先用国内镜像源：

```bash
bash deploy.sh --mirror
```

脚本会自动完成：

1. 检查 Docker / Docker Compose 环境
2. 从 `.env.example` 生成 `.env`（首次运行）
3. 准备 `config.json` 与数据目录（`data/ state/ logs/ images/ jsonl/ price_history/`）
4. 拉取镜像（默认 `ghcr.io`；`--mirror` 时按序自动尝试国内镜像源候选池
   `ghcr.m.daocloud.io` → `ghcr.nju.edu.cn` → `ghcr.geekery.cn`，直到拉通，与 `ghcr.io` 互为回退）
5. 启动容器并做健康检查，最后打印访问地址

## 三、填写配置（首次必做）

首次运行会新建 `.env`，**AI 分析功能必须填入有效的 API Key 才能工作**。编辑 `.env`：

```bash
vi .env
```

至少配置以下项：

| 变量 | 说明 |
| --- | --- |
| `OPENAI_API_KEY` | AI 模型 API Key |
| `OPENAI_BASE_URL` | 兼容 OpenAI 格式的接口地址 |
| `OPENAI_MODEL_NAME` | 模型名称（**必须支持图片分析 / Vision**） |
| `WEB_USERNAME` / `WEB_PASSWORD` | Web 管理界面账号密码（**务必修改默认的 admin/admin123**） |

改完后让配置生效：

```bash
bash deploy.sh --update
```

## 四、访问与登录闲鱼账号

1. 浏览器打开 `http://<服务器IP>:5352`，用 `.env` 里的账号密码登录。
2. 进入「闲鱼账号管理」，用 [Chrome 扩展](https://chromewebstore.google.com/detail/xianyu-login-state-extrac/eidlpfjiodpigmfcahkmlenhppfklcoa) 导出闲鱼登录态 JSON 并粘贴导入。
3. 登录态会保存到 `state/` 目录（如 `state/acc_1.json`）。

> Docker 部署下爬虫固定使用容器内置的 Chromium 且以无头模式运行，因此**必须通过 Web UI 导入登录态**，无法在容器里手动扫码登录。

## 五、常用运维命令

| 操作 | 命令 |
| --- | --- |
| 部署 / 重新部署 | `bash deploy.sh` |
| 更新到最新镜像并重启 | `bash deploy.sh --update` |
| 查看实时日志 | `bash deploy.sh --logs` |
| 停止并移除容器 | `bash deploy.sh --down` |
| 从源码本地构建（不用预构建镜像） | `bash deploy.sh --build` |

## 六、端口与防火墙

- 默认端口 `5352`。若要改端口，先改 `.env` 里的 `SERVER_PORT`，再同步修改 `docker-compose.yaml` 的端口映射 `"5352:5352"`（宿主机端口:容器端口两者需一致），然后 `bash deploy.sh --update`。
- 云服务器需在安全组 / 防火墙放行 `5352` 端口。
- **建议**：不要把 5352 端口直接暴露公网，前面套一层 Nginx 反向代理并配置 HTTPS，同时确保已修改默认 Web 密码。

## 七、数据持久化

以下目录通过 volume 挂载到宿主机，容器重建不会丢数据：

| 目录 | 内容 |
| --- | --- |
| `data/` | SQLite 主库（`app.sqlite3`） |
| `state/` | 闲鱼登录态 cookie |
| `config.json` | 监控任务配置 |
| `prompts/` | AI 分析 prompt 文件 |
| `jsonl/` | 抓取结果数据 |
| `images/` | 商品图片 |
| `logs/` | 运行日志 |
| `price_history/` | 价格历史 |

备份时打包上述目录即可。

## 八、常见问题

- **镜像拉取很慢 / 拉不动**（国内常见）：按以下顺序尝试：
  1. 优先用国内镜像源：`bash deploy.sh --mirror`。脚本内置多个 ghcr 加速源候选池
     （`ghcr.m.daocloud.io` → `ghcr.nju.edu.cn` → `ghcr.geekery.cn`），会**按序自动尝试直到拉通**。
  2. 换其它 ghcr 代理：`IMAGE_MIRROR=<你的代理地址>/usagi-org/ai-goofish:latest bash deploy.sh --mirror`
     （自定义源会优先于内置候选池尝试）。
  3. 给 Docker 配置国内 registry 加速器（加快构建时拉取 python/node 等基础镜像）：
     编辑 `/etc/docker/daemon.json`：
     ```json
     {
       "registry-mirrors": [
         "https://docker.1ms.run",
         "https://docker.mirrors.ustc.edu.cn"
       ]
     }
     ```
     然后 `sudo systemctl daemon-reload && sudo systemctl restart docker`。
     （注：`registry-mirrors` 只加速 Docker Hub 镜像，不影响 `ghcr.io`，主要用于 `--build` 模式。）
  4. 实在拉不到，用源码本地构建：`bash deploy.sh --build`。
- **容器起来了但打不开页面**：`bash deploy.sh --logs` 看日志；确认防火墙 / 安全组放行了端口。
- **AI 分析报错**：检查 `.env` 的 `OPENAI_*` 配置，并确认所用模型支持图片（Vision）；可临时开 `AI_DEBUG_MODE=true` 看详细日志。
- **任务反复失败被暂停**：多为登录态失效，重新在 Web UI 导入 `state`。
